## 1. 教程文档

### 1.1 我们要完成什么

这套课程要训练一只 MicroDuck 机器人完成足球任务：

1. 观察自己、足球和球门的位置。
2. 决定下一步动作。
3. 接近足球并调整朝向。
4. 把足球踢向球门。
5. 将仿真中学到的策略迁移到真实机器人。

传统编程通常要求我们提前写出完整规则：

```text
如果球在左边，就向左转；
如果球很远，就向前走；
如果球在脚边，就执行踢球动作。
```

问题是，真实情况远比这些规则复杂。足球可能出现在任何位置，地面摩擦会变化，摄像头会产生误差，电机也存在延迟。规则数量很快就会失控。

强化学习采用另一种思路：我们不直接告诉机器人每一步应该怎么做，而是定义目标和奖励，让机器人通过反复尝试寻找有效策略。

### 1.2 什么是强化学习

强化学习包含五个核心概念：

| 概念 | 在足球项目中的含义 | 示例 |
|---|---|---|
| 智能体 Agent | 做决定的学习者 | MicroDuck |
| 环境 Environment | 智能体活动的世界 | 足球场、足球、球门 |
| 状态 Observation | 智能体当前看到的信息 | 球的相对位置、机器人朝向 |
| 动作 Action | 智能体可以执行的选择 | 前进、左转、右转、踢球 |
| 奖励 Reward | 环境对动作结果的评分 | 接近球 `+0.1`、进球 `+100` |

一次完整交互如下：

```text
观察状态 → 选择动作 → 环境变化 → 获得奖励 → 更新策略 → 再次观察
```

这个过程会不断循环。机器人最初几乎是随机行动；积累足够经验后，它会逐渐提高有效动作出现的概率。

### 1.3 用最小代码理解学习循环

```python
observation, info = env.reset()
terminated = False

while not terminated:
    action = policy.predict(observation)
    observation, reward, terminated, truncated, info = env.step(action)
    policy.learn(observation, action, reward)
```

逐句解释：

- `env.reset()`：重置球场，返回机器人第一次看到的状态。
- `while not terminated`：只要还没有进球或失败，就继续本回合。
- `policy.predict(observation)`：策略根据当前状态选择动作。
- `env.step(action)`：执行动作，并返回新状态、奖励和结束信息。
- `policy.learn(...)`：利用交互结果改进策略。这一行是概念写法，后续会用 PPO 完成真正更新。

代码规范：

- 使用 `observation`，避免模糊缩写 `obs` 出现在初学代码中。
- 区分 `terminated` 与 `truncated`：前者表示任务自然结束，后者表示达到时间限制。
- 每个循环只调用一次 `env.step()`，防止状态和奖励错位。
- 正式训练必须设置最大步数，避免机器人永远原地转圈。

### 1.4 为什么不能直接训练完整足球任务

如果机器人一开始离球很远，而奖励只在进球时出现，那么随机策略可能几百万步都得不到一次正奖励。AI 无法知道哪个动作正在让它接近目标。

因此，我们把项目拆成六个能力关卡：

1. 学会稳定移动。
2. 学会寻找足球。
3. 学会接近足球。
4. 学会触球和带球。
5. 学会朝球门射门。
6. 完成 Sim2Real 迁移。

这种从简单任务逐步升级的方法叫做课程学习（Curriculum Learning）。

### 1.5 项目技术路线

```text
Gymnasium 足球环境
        ↓
设计状态、动作和奖励
        ↓
Stable-Baselines3 PPO 训练
        ↓
固定环境评估成功率
        ↓
Sim2Real 域随机化
        ↓
导出策略并部署到 MicroDuck
```

本项目使用：

- Gymnasium：定义统一的足球训练环境接口。
- Stable-Baselines3 PPO：训练策略网络与价值网络。
- NumPy：处理状态向量和二维运动。
- TorchScript：导出可部署模型。
- Mac mini M4：完成环境运行、训练和策略导出。

### 1.6 本集练习

请先不写训练算法，只回答下面的问题：

1. MicroDuck 在这个项目中是智能体还是环境？
2. “球在机器人右前方 30 厘米”属于状态、动作还是奖励？
3. “向左转”属于什么？
4. “足球进入球门获得 +100”属于什么？
5. 为什么进球奖励不能是唯一奖励？

完成标准：能够不看表格，说出 Agent、Environment、Observation、Action 和 Reward 在足球任务中的对应关系。

## 5. B站解说稿

### 开场

大家好，欢迎来到 MicroDuck 足球强化学习课程。

先看这个画面：这只小鸭刚开始完全不会踢球。它可能往反方向走，可能原地转圈，也可能一脚踢空。但是经过大量尝试以后，它居然能自己找到球，再把球踢进球门。

注意，我们没有给它写一套“球在左边就左转”的固定程序。我们要做的是告诉它：什么情况算做得好，什么情况算做得不好，然后让它自己学习。

### 什么是强化学习

这就是强化学习。

你可以把它想成训练宠物。做对了，给一点奖励；做错了，给一点惩罚。尝试次数足够多以后，它就会慢慢找到更容易得到奖励的行为。

在我们的足球项目里，一共有五个最基本的角色。

第一，智能体，也就是做决定的 MicroDuck。

第二，环境，也就是足球场、足球和球门组成的世界。

第三，状态。比如足球在小鸭的左边还是右边，距离有多远，小鸭现在朝向哪里。

第四，动作。我们先给它五个选择：等待、前进、左转、右转和踢球。

第五，奖励。接近足球可以得到一点小奖励，远离足球会扣分，碰到球会得到更明显的奖励，最后进球得到最高奖励。

### 学习循环

把这五个概念连起来，就是一个循环。

小鸭先观察现在的状态，再根据策略选择动作。环境执行这个动作以后，把新的状态和奖励交回来。训练算法再根据这些结果调整策略，然后进入下一步。

屏幕右边的代码正在做同一件事。`reset` 表示开一个新回合，`predict` 表示根据观察选择动作，`step` 表示让环境向前运行一次。大家一定要注意，Gymnasium 的 `step` 会返回五项内容，其中 `terminated` 是任务自然结束，`truncated` 通常是达到最大步数。这两个概念后面写环境时会经常用到。

### 为什么需要拆任务

那我们是不是可以直接让 AI 开始踢球？理论上可以，实际上效率会非常低。

想象一下：如果小鸭离足球很远，而且只有进球才能得分，那么随机动作可能尝试几十万次都碰不到球。它根本不知道自己有没有变好。

所以整个项目会像打游戏一样拆成六关。

第一关学会移动；第二关学会找球；第三关学会接近球；第四关学会触球和带球；第五关学会射门；第六关才把仿真策略迁移到真实机器人。

这种从简单到困难的训练方式，就是课程学习。

### 项目规划

技术上，我们会先用 Gymnasium 建立一个标准足球环境。然后定义状态空间、动作空间和奖励函数，再使用 Stable-Baselines3 的 PPO 算法训练。

训练曲线变好不代表任务一定学会了，所以我们还会建立固定评估环境，真正统计进球率。

接下来是 Sim2Real。仿真里的摩擦力很稳定，真实地面却可能是木板、草地或者地毯；真实摄像头还有噪声，电机也有延迟。我们会用域随机化，让这些参数在训练时不断变化，使策略不依赖某一个完美世界。

最后，我们会把策略导出，并在速度和关节范围受限的条件下测试真实 MicroDuck。

### 结尾

这一集不要求大家马上训练模型。你只需要记住一件事：强化学习不是让机器人盲目乱试，而是通过状态、动作和奖励，系统地学习一个策略。
